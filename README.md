# LuchClock

Контроллер башенных часов на базе **ESP8266 NodeMCU 1.0 (ESP-12E)**. Проект находится на стадии разработки: веб-интерфейс и сетевые функции реализуются до подключения силового оборудования.

## Текущее состояние — v0.3

| Компонент | Состояние |
| --- | --- |
| Wi-Fi | Подключение и повторные попытки соединения |
| Веб-интерфейс | Работает через встроенный HTTP-сервер ESP8266 |
| NTP | Реализована синхронизация и контроль её актуальности; требуется проверка на устройстве |
| Часовой пояс | Минск, UTC+3 (`MSK-3`) |
| Режимы | Автоматический и ручной; переключаются через API |
| Ручные команды | Только симуляция, без управления GPIO |
| Журнал | До 20 событий в RAM; после перезапуска очищается |
| AS5600 и положение стрелок | Пока не подключены и не определяются |
| Авторизация и постоянный IP | Запланированы, пока не реализованы |

**Важно:** выбор автоматического режима пока не приводит к движению двигателя. Это прототип, не готовый к управлению силовой установкой.

## Структура проекта

```text
LuchClock/
├── LuchClock.ino          # setup() и loop()
├── config.h               # Общие настройки, подключение secrets.h
├── secrets.example.h      # Пример локальных параметров Wi-Fi
├── wifi_manager.h/.cpp    # Wi-Fi и диагностика подключения
├── time_manager.h/.cpp    # NTP, местное время и состояние синхронизации
├── web_server.h/.cpp      # HTTP-сервер, API, журнал в RAM
├── web_ui.h               # Действующий HTML, CSS и JavaScript в PROGMEM
└── data/
    ├── index.html         # Пока пустой файл
    ├── style.css          # Пока пустой файл
    └── app.js             # Пока пустой файл
```

Файлы в `data/` **пока не используются прошивкой**. Веб-страница встроена в `web_ui.h`; загрузка файлов через LittleFS ещё не настроена.

## Подготовка и прошивка

1. Установить Arduino IDE и поддержку плат ESP8266.
2. Скопировать `secrets.example.h` в `secrets.h` рядом с `LuchClock.ino`.
3. Заполнить `WIFI_SSID` и `WIFI_PASSWORD` в локальном `secrets.h`. **Не добавлять этот файл в Git.**
4. Открыть `LuchClock.ino` в Arduino IDE.
5. Выбрать плату **NodeMCU 1.0 (ESP-12E Module)** и соответствующий COM-порт.
6. Собрать и загрузить прошивку.
7. Открыть монитор порта со скоростью **115200 бод**, дождаться подключения Wi-Fi и узнать IP-адрес.
8. Открыть `http://<IP-устройства>/` в браузере из доступной сети.

Если точное время не появляется, проверить доступность NTP-серверов и UDP-порта 123 в сети организации. Параметры серверов находятся в `config.h`.

## API (текущий прототип)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Веб-интерфейс |
| GET | `/api/status` | Wi-Fi, режим, время и состояние NTP |
| GET | `/api/events` | Последние события из RAM |
| POST | `/api/mode?value=auto` | Выбор автоматического режима |
| POST | `/api/mode?value=manual` | Выбор ручного режима |
| POST | `/api/command?action=forward` | Имитация движения вперёд |
| POST | `/api/command?action=backward` | Имитация движения назад |
| POST | `/api/command?action=stop` | Имитация остановки |

Сейчас API **не защищён авторизацией**. Не открывать доступ к нему из интернета или недоверенных сетей.

## Безопасность

Проект рассчитан на будущую работу с реверсивным пускателем и трёхфазным двигателем. До физического подключения обязательны независимые аппаратные блокировки встречного включения, электрозащита, безопасное состояние выходов при перезагрузке и испытания без силовой нагрузки. Программные проверки не заменяют аппаратную защиту.

Локальный файл `secrets.h` исключён через `.gitignore`; в репозитории хранится только `secrets.example.h`.
