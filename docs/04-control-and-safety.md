# Управление, безопасность и системное время

## Режимы

OFF / MANUAL / AUTO. Каждый старт или перезапуск — OFF, без автозапуска. OFF немедленно выключает выход; при разрешённой смене режима привод остановлен и действует защитная пауза. MANUAL не переходит самостоятельно в AUTO. При недостоверном энкодере активный режим переводится в OFF; при потере данных во время движения — немедленный стоп и защёлкнутая авария. Новые запуски при unhealthy запрещены. AUTO требует известного часа и свежего времени, здорового энкодера, отсутствия аварии/паузы; калибровка не обязательна. Реального алгоритма движения AUTO в v1.19 нет.

## Защитные интервалы

- Непрерывное движение: MANUAL/AUTO по умолчанию 900 с, максимум через настройки 900 с (предварительно для стенда).
- MANUAL: по лимиту стоп, предупреждение, пауза по умолчанию 15 с, только новая явная команда. Пауза не должна сокращаться изменением настроек; AUTO в паузе запрещён. OFF доступен.
- AUTO: по лимиту критическая блокировка и OFF, явный сброс, не запускающий мотор. Возобновление AUTO проектируется отдельно.
- При отсутствии подтверждённого движения 300 с по умолчанию — критическая авария, стоп, OFF, явный сброс.
- Пауза остановки и смены режима: по 1000 мс, фиксированы. Дополнительный скользящий лимит не вводить.
- Управление GPIO только из моторного модуля. Таймеры считает ESP монотонно через millis(), браузер лишь отображает. Сброс аварии только в OFF при healthy датчике; не сбрасывать автоматически при восстановлении I²C/NTP/питания.

## NTP и Wi-Fi

Штатный SNTP ESP8266, configTime один раз при setup; дополнительный ручной вызов каждые 3600 с удалён. Повторная синхронизация наблюдалась примерно через час в предыдущих испытаниях; пользователь 26.11 сообщил о синхронизации ESP-12. Не считать это измерением дрейфа или гарантией периода для всех сетевых условий. Отдельно проверить суточный дрейф без NTP.

Различать наличие системного времени и свежесть последней успешной синхронизации; возраст монотонный 64-битный, события первого sync/stale/recovered/изменения порога. Порог — не частота запросов. Решение 26.11: default 24 ч (86400 с), настройку оставить. В 26d079c пока default 3 ч (10800 с), изменение кода впереди. Сохранённые пользовательские значения не перезаписывать без отдельного решения. При устаревании блокировать автоматическое движение, ручное управление доступно при соблюдении остальных защит. Политику автоматического возобновления после NTP согласовать в этапе AUTO. Журнал и UI показывают устаревание/восстановление, Zabbix позже.

Wi-Fi STA, persistent(false), autoReconnect и неограниченные повторные попытки (10 с по умолчанию), диагностика при изменениях и каждые 15 с без связи. Потеря Wi-Fi и потеря интернета различны.

## Потеря питания

Если ESP и датчик продолжают наблюдение от UPS, час сохраняется в RAM; отсутствие силового питания само по себе не меняет команду до достижения цели или штатной защиты. Возвращение питания до аварии позволяет будущему AUTO продолжить обычную коррекцию по достоверному времени, новая синхронизация не обязательна. После аварии сохраняется блокировка. При перезапуске или потере непрерывности час неизвестен. Никаких специальных режимов UPS/датчика питания.

Инцидент старой прошивки: четыре механизма ушли вперёд на час после предполагаемого сбоя питания. Причина не установлена; гипотеза — движение почти на оборот от позиции 124 к 123 или потеря часа. Не считать гипотезу доказанной.
