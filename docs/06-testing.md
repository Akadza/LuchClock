## До выпуска стендовой v1.19

1. Воспроизвести проблемы тестами (red → green → refactor), без отключения существующих проверок.
2. Проверить первый шаг после старта/перекалибровки, исчерпание бюджета, смешанные аномалии, invalid codes, подтверждения 2–5, разрыв опроса и переполнение millis().
3. Интеграция реальных модулей: декодирование → нормализация → калибровка → фильтр → час → защита. Проверить каждый переход часа, 12:00, ненулевое смещение, дрожание/пропуски, аномалии до/на/после границы, половину оборота, потерю I²C, восстановление без восстановления часа, калибровку без движения.
4. Проверить команды OFF/MANUAL/AUTO, ручной час, AUTO без сохранённой калибровки при выполнении иных условий, stale NTP, ручной режим при stale, защитные лимиты/паузы/аварии, сброс без запуска, настройки и сохранение, HTTP и UI.
5. Добавить Arduino CLI сборку ESP8266 (предлагаемый FQBN esp8266:esp8266:nodemcuv2; сверить версию core с реальной средой и закрепить). Использовать secrets.example.h вместо реальных credentials. Сборка и тесты на рабочей ветке; фиксировать результат и SHA. Не мигрировать на PlatformIO ради CI.
6. После зелёных проверок изменить FIRMWARE_VERSION на 1.19, повторить CI. Не сливать в main без решения.

## Стенд (пользователь)

С отключённой силовой частью: питание/перезапуск OFF, измерение GPIO, чтение ACE-128, ручной шаг примерно каждые 5–6 с при номинальной скорости, нулевая/ненулевая калибровка, часовые границы, остановка при потере I²C и отсутствие самозапуска, таймеры и аварии, Wi-Fi/SNTP, долгий loop/heap/max free block. Для ускорения допустимы отдельно согласованные стендовые настройки скорости; не ослаблять защиту для реального двигателя. Записать точный SHA, core, плату, условия и наблюдения. Проверить сохранение EEPROM и потерю питания безопасно.

Будущие аппаратные сценарии с AUTO: пропадание силового питания при работающем ESP, возврат до/после аварии, разряд UPS, потеря сети, переход 12:00, отсутствие лишнего оборота при неизвестном часе. Не объявлять HIL успешным без физической проверки.
