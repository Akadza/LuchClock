# Веб-интерфейс и диагностика

## Требования

Действующая страница — src/web/web_ui.h, PROGMEM. data/index.html, style.css, app.js пустые и не используются. LittleFS-миграция не входит в текущую задачу.

Сохранить существующий характер панели промышленного прибора: компактная тёмная поверхность, единая шкала отступов, спокойная типографика, табличные цифры, цвет только по смыслу. Применять Unslop выборочно, без декоративной переработки. На desktop сохранить компактную панель и прокрутку журнала, на мобильном — читаемость и доступность управления.

Время ESP и положение стрелки, режимы, ручные кнопки вперёд/стоп, установка часа, диагностика, журнал, отдельный диалог настроек по шестерёнке. Нет реверса. OFF — информационный текст. Авто не обещает реального движения. Таймер ручной работы и шкала отображают данные ESP; в AUTO внутренний лимит без полосы непрерывного движения. Смена режимов может иметь собственную шкалу ожидания.

API — единственный источник разрешений. При потере связи блокировать команды и настройки, не показывать старые данные как свежие. Установка часа должна получать отдельное разрешение сервера (ещё не реализовано). В диагностике различать связь PCF8574, подтверждённую позицию, подозрительные данные (последнее подтверждённое значение с предупреждением) и недостоверность (нет данных). Показывать известность часа отдельно от минут, сырой код и смещение только для диагностики. Не требовать обязательной калибровки.

Настройки: открытие загружает актуальные значения; Apply временно до перезапуска, Save применяет и сохраняет. Без изменений кнопки недоступны, кроме ранее применённых несохранённых данных. Изменения только OFF/MANUAL при остановке и без перехода. Не закрывать диалог во время записи; отбрасывать несохранённый ввод при закрытии. Калибровка одной кнопкой, guard без лишнего сообщения, ошибки не скрывать.

## Журнал

20 важных событий в RAM, без постоянной записи. Время события или относительный uptime до NTP. Типизированные code/level, нейтральный info, приглушённый жёлтый warning и красный critical, компактные иконки. Не засорять журнал штатными подробностями; Serial для подробной диагностики. Будущий сервер хранит 2–3 дня, Zabbix критические состояния.

## Состояние и задачи

26d079c: UI уже получает can_* и encoder_healthy, но не использует здоровье для всех отображений, начальная разметка может показать AUTO при OFF, разрешение задания часа вычисляется в JS. Проверить эти случаи, ошибки калибровки, тайм-ауты запросов, восстановление журнала, несколько клиентов и малую высоту экрана. Существующий тайм-аут fetch 5 с включает чтение тела; опрос status 400 мс, журнала 10 с. Не менять дизайн без необходимости.

### Исправления 26.11

API can_set_clock_hour использует тот же предикат, что команда установки часа. UI показывает OFF при первом открытии, маркирует неподтверждённые показания как последние, очищает показания при потере API, отображает причину блокировки AUTO. calibration_current требует healthy. Проверка на устройстве ещё не выполнена.

### Требование пользователя 26.11

Активный OFF/MANUAL/AUTO визуально выделять даже если кнопка disabled: отдельное устойчивое оформление выбранного режима, отличное от неактивных запрещённых вариантов (акцентная рамка/фон и читаемая надпись). Не ослаблять серверные запреты и не обозначать недостоверное состояние как подтверждённое. Проверить все три режима, защитную паузу и потерю API. При внедрении AS5600 показать тип датчика и его разрешение в диагностике, не привязывать UI к 127 или PCF8574. Реализация UI отложена до следующего этапа.
